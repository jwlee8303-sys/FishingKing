## 2. 공통 정보 구조와 내비게이션

### 일반 페이지

모바일은 상단 제목/계정 상태 + 스크롤 본문 + 하단 주요 메뉴 5개(홈·낚시·도감·랭킹·내 정보)로 설계합니다.
로그인은 상단 계정 동작과 내 정보 화면에서 접근하며 비회원 접근 버튼을 같은 화면에서 제공합니다.
6개 항목을 좁은 하단 바에 모두 압축하지 않습니다. 모든 터치 대상은 최소 44×44 CSS px입니다.
하단 바 높이는 56px + bottom safe inset, 본문 하단 여백은 이 높이 이상 확보합니다.
모바일 가로 일반 페이지도 세로 스크롤을 허용하고, 높이가 짧으면 하단 바 대신 상단 메뉴로 동일 동선을 제공합니다.

PC는 기존 헤더의 주요 메뉴를 유지·확장하고 내 정보/로그인을 계정 영역에 둡니다.
현재 메뉴의 로그인 링크를 내 정보/계정 진입으로 정리하는 것은 3-04 변경안이며 이번 코드에는 적용하지 않습니다.
태블릿에서는 터치 대상 크기를 유지한 채 2열 본문과 상단 내비게이션을 사용합니다.
현재 본문 바로가기·main 포커스·NavLink 활성 표시를 유지하며 페이지 전환 시 제목/본문 포커스 규칙을 적용합니다.

### 게임 페이지

게임 중에는 일반 헤더/footer/하단 메뉴를 게임 영역 위아래에 중복 표시하지 않습니다.
React GameShell이 HUD·메뉴·조작 영역을 배치하고 PixiJS는 지정된 중앙 영역만 그립니다.
항상 보이는 44px 이상 메뉴 버튼으로 일시정지/도감/랭킹/내 정보/로그인/홈에 접근합니다.
메뉴를 열면 입력을 취소하고 모의 세션을 일시정지합니다. 오버레이 닫기는 누른 상태를 자동 복원하지 않습니다.
다른 화면 이동 시 입력 취소·모의 세션 보존/종료 안내를 제공하며 실제 서버 게임의 중단 정책은 5단계에서 확정합니다.

### 주요 동선

| 시작 | 동작 | 도착 및 계정 정책 |
| --- | --- | --- |
| 메인 | 낚시 시작 | /game, 로그인 강제 없음. 3단계는 모의 조작임을 표시 |
| 모든 일반 화면 | 하단/상단 도감 | /collection, 본인이 발견한 물고기만 기본 표시 |
| 게임 | 메뉴 → 도감/랭킹/내 정보 | 입력 해제 후 해당 화면, 비회원도 접근 경로 유지 |
| 비회원 내 정보 | 로그인 | /login, 로컬 임시 기록/서버 기록 차이를 안내 |
| 로그인 | 비회원으로 계속 | 안전한 내부 returnTo 또는 /game |
| 로그인 성공(4단계) | 돌아가기 | 허용된 내부 경로만 사용. 외부 URL을 returnTo로 실행하지 않음 |
| 알 수 없는 경로 | 홈으로 이동 | 기존 404 유지 |

비회원 기록은 현재 탭의 임시/모의 데이터라는 기본 설계입니다. 새로고침·기기 변경 후 보존, 로그인 시 병합을 약속하지 않습니다.
정식 랭킹 제출·서버 동기화·기록 검증은 4~6단계 전까지 동작한다고 표시하지 않습니다.

### S01 메인 — /

목표: 휴대폰에서 로그인 없이 플레이 진입과 현재 모드를 바로 이해한다.

| 구성 | 모바일 세로 | PC / 태블릿 / 모바일 가로 |

| 주 콘텐츠 | 짧은 소개·대표 배경·큰 낚시 시작 버튼 | 대표 영역 2열: 소개/시작 + 장면 미리보기 |

3단계 데이터는 훈련/모의 배지를 붙이고, 잔액·경험치·최고 기록 같은 미확정 수치를 실제 계정 데이터처럼 보여주지 않습니다.
제안 컴포넌트: HomeHero, StartFishingButton, DiscoverySummary, QuickLinkCard, ModeBadge.

포획 성공·판정·보상 UI는 5단계 규칙과 연결될 예정입니다. 3단계는 입력 활성/해제와 모의 반응만 표현합니다.
정확한 배치·명령·취소 규칙은 MOBILE_GAME_UX를 단일 기준으로 사용합니다.

### S03 물고기 도감 — /collection

**기본 데이터 집합은 현재 사용자가 발견한 물고기뿐입니다.** 미발견 이름/이미지/실루엣 목록이나 전체 종 수를 기본 노출하지 않습니다.
필터·검색·정렬·발견 수는 이 집합 안에서만 동작합니다. 0건이면 빈 상태와 낚시 진입 버튼을 표시합니다.
필터 결과 0건과 아직 아무것도 발견하지 않은 상태를 구분합니다. 임의 전체 목록으로 빈 화면을 채우지 않습니다.

| 구성 | 모바일 | PC / 태블릿 |
| --- | --- | --- |
| 상단 | 제목, 발견 수, 검색·필터 버튼 | 제목·검색·정렬 도구 모음 |
| 목록 | 기본 2열 카드, 큰 글자/매우 좁은 폭은 1열 | 가용 폭에 따라 3~5열, 필터 패널 |
| 상세 | 카드 선택 → 상세 sheet/전체 높이 패널 | 우측 상세 패널, 목록 선택 보존 |
| 상세 정보 | 이름·이미지·발견 이력, 값이 없으면 미기록 | 같은 정보, 없는 기록을 0으로 위조하지 않음 |

미발견 ID로 접근하면 상세를 노출하지 않고 발견 도감으로 복귀합니다. 실제 권한/데이터 필터링은 4·6단계 서버 측에서도 보장해야 합니다.
비회원은 해당 임시 세션의 발견 자료만 사용합니다. 3단계 fixture가 필요하면 발견된 자료와 모의 배지를 명시합니다.
제안 컴포넌트: DiscoveryFilterBar, FishGrid, DiscoveredFishCard, FishDetailPanel, CollectionEmptyState.

계정 변경·로그아웃·데이터 보존 의미는 4단계 인증 계약에 맞춥니다. 현재 동작하는 것처럼 표시하지 않습니다.

제안 컴포넌트: LoginFormLayout, FormField, InlineError, SubmitStatus, ContinueAsGuest, ReturnLink.

## 4. 로딩·빈 데이터·오류·비회원 상태 계약

상태는 색상 외에 문구/아이콘/접근 가능한 이름으로 구분합니다. 로딩 영역 크기를 예약해 버튼이 튀지 않게 합니다.
오류가 발생해도 메뉴·뒤로가기·재시도는 44px 이상으로 유지합니다. 시크릿/토큰/내부 오류 원문은 표시하지 않습니다.

| 화면 | 로딩 | 빈 상태 | 오류/부분 실패 |
| --- | --- | --- | --- |
| 메인 | 요약 카드 skeleton, 시작 버튼은 가능한 한 독립 | 발견 이력 없음 안내 | 요약 실패와 전체 앱 실패 분리, 텍스트/시작 동선 유지 |
| 게임 | 자산별 진행/재시도·종료, 조작은 비활성 | 자산 미제작/훈련 준비 문구 | 핵심 장면 실패는 안전 정지, 장식 실패는 대체 이미지, 무한 spinner 금지 |
| 도감 | 카드 skeleton, 발견 여부 판정 전 전체 종 목록 금지 | 발견 0건 / 검색 0건 별도 | 이전 발견 목록이 있으면 오래된 자료 배지, 재시도 |
| 랭킹 | 행 skeleton, 기간 상태 유지 | 미집계 / 미참가 별도 | 서버 연결 실패, 갱신 실패 시 마지막 갱신 시각 유지 |
| 프로필 | 계정 확인 중·요약 skeleton | 비회원/기록 없음 | 계정 확인 실패를 비회원 확정으로 오인하지 않음 |
| 로그인 | 제출 중 중복 제출 차단·상태 문구 | 초기 입력 상태 | 필드 오류·네트워크 오류·인증 실패 구분, 비밀정보 로그 금지 |

모든 화면에서 이미지 로딩 실패 시 동일한 예약 영역의 기본 이미지/텍스트 대체를 사용합니다.
버튼의 disabled·pressed·focused·loading·error 상태를 별도로 설계합니다. 입력 처리 상세는 MOBILE_GAME_UX에 정의합니다.
리스트 상세/메뉴 sheet는 focus trap·닫기·Escape·원래 트리거로 포커스 복귀를 제공합니다.
게임 입력 단축키는 폼/대화상자/게임 외 화면에서 작동하지 않습니다.

## 5. 반응형·재사용·접근성 계획

| 기준 viewport | 일반 화면 | 게임 | 검증 포인트(후속 수행) |
| --- | --- | --- | --- |
| 320×568 | 단일 열, 하단 5개 메뉴 | 세로 compact HUD+하단 조작 | 메뉴/CTA 44px, 텍스트 줄바꿈, 도감 1~2열 |
| 390×844 | 단일 열·2열 도감 카드 | 기본 세로 배치 | 엄지 접근·Safe Area·긴 오류 문구 |
| 430×932 | 같은 구조, 콘텐츠 여백 확장 | 세로 장면 높이 증가 | 버튼을 단순 확대/멀리 배치하지 않음 |
| 844×390 | 상단 메뉴, 높이 짧으면 본문 스크롤 | 좌우 조작 + 넓은 장면 | 좌우 inset, 버튼 세로 잘림 금지 |
| 768×1024 | 터치 유지, 2열 요약 | 세로 태블릿 장면 + 하단 조작 | PC 축소판으로 대체하지 않음 |
| 1440×900 | 기존 max-width 헤더/본문 확장 | PC 장면+정보+키 안내 | 마우스/키보드와 같은 명령 실행 |

기존 3-01 측정에서 홈 38×40, 나머지 메뉴 높이 40px입니다.
3-04 개선 대상으로 NavLink·계정/메뉴/닫기·필터·탭·게임 버튼 모두 min-width/min-height 44px을 명시합니다.
본문 16px 기준, 작은 보조 정보는 충분한 대비·줄 간격을 사용합니다. 최대 확대/텍스트 확대 시 가로 잘림을 숨기지 않습니다.
적응 기준은 폭뿐 아니라 사용 가능 높이·방향·pointer 특성입니다. 작은 가로 화면을 데스크톱 배치로 단순 전환하지 않습니다.

재사용: AppLayout의 Outlet/활성 메뉴/본문 이동/포커스 규칙, 기존 페이지 파일과 404를 유지합니다.
일반 AppShell과 전용 GameShell은 같은 상위 내비게이션 정의를 공유하도록 3-04에서 확장합니다.
PagePlaceholder는 준비 안내에만 쓰고, 모든 화면의 로딩/오류를 같은 준비 카드로 대체하지 않습니다.
아직 없는 UI 컴포넌트는 위 제안 이름이며 기존 구현으로 보고하지 않습니다.
